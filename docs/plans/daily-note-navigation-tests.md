## Affected surfaces

- Obsidian's Markdown note header, in source and reading modes.
- The calendar opened by the header date.
- Core Daily Notes configuration, which controls recognition.
- Multiple panes, pinned panes, and pop-out windows.
- The command palette and user-assigned shortcuts in Settings → Hotkeys.

Use a separate durable test vault outside the Conductor workspace. Include a daily-note history with gaps, at least two years, a leap day, and an ordinary note with a date-like filename outside the configured folder. Include an empty-history and one-note case. Repeat recognition checks with the vault root and a custom folder/date format containing subfolders.

## Key interactions to verify

1. Open a daily note. The center breadcrumb becomes previous, clickable `YYYY-MM-DD`, and next, with no dropdown indicator. History buttons and other header actions remain usable.
2. Previous and next open neighboring existing daily notes in the originating pane and skip gaps. At either end, the unavailable arrow is disabled. One note disables both arrows.
3. Click the date, change month/year, and open an old existing note. The picker closes and the header updates. Returning through ordinary Obsidian history works.
4. Missing dates are visibly unavailable and cannot open anything with pointer or keyboard. Today is disabled if today's note does not exist.
5. Open an ordinary note. Its normal breadcrumb returns. Another pane containing a daily note still has its own correct navigator.
6. Change core Daily Notes folder/format. Recognition moves to the new setting, without retaining stale navigation from the old folder. Root-folder configuration does not pick up unrelated files unless their complete relative paths match the configured date format.
7. In an eligible daily note, invoke the plugin's Open date picker and Open today's existing daily note from the command palette. Assign each a shortcut through Obsidian's Hotkeys settings in the fixture vault and repeat in reading/source modes and a pop-out. Only these two commands are added; core previous/next entries and existing shortcuts remain unchanged. The existing-today action is unavailable when today's note is missing.
8. Command availability checks cause no navigation, focus changes, notices, or DOM changes. Execution rechecks the current pane and target; changing notes or deleting a target between checking and execution must not open a stale target or create a file. The picker command is unavailable on ordinary notes or a hidden/unmounted header. Unloading removes only this plugin's command registrations.

## Edge cases

- Invalid date, missing year, leap day, ordinal date, ISO week date, literal text, localized month names, and conflicting date-derived folders.
- Empty calendar month, earliest/latest year, invalid year input, missing today, midnight rollover, timezone/DST changes.
- Rename or delete a target while the picker is open; update the folder configuration while a note remains open.
- Click rapidly; navigate away or close the originating pane during navigation. No stale date should appear in another pane.
- Pinned panes, two daily notes side by side, a deferred background tab, and a pop-out window.
- Narrow pane, default and Dracula themes, hidden note header, source/reading mode switches, and title DOM replacement.
- Disable/re-enable the plugin repeatedly. No duplicated controls, blank breadcrumbs, open orphaned dialogs, or continued observers/callbacks.
- Disable core Daily Notes or make its settings unreadable. Normal header remains usable with a single explanation; no guessed folder.

## Critical paths

**Plugin guidelines:** Run the official Obsidian ESLint rules, typecheck, tests, and production build. Inspect manifest fields, ID/folder agreement, synchronized plain version numbers, version compatibility mapping, and packaged assets. Check README behavior claims against the implementation and verify dependency licenses before distribution. Review both lint warnings and errors. Validate the scoped styles, calculated positioning, and restoration in actual main/pop-out windows. See [the guidelines review](obsidian-plugin-guidelines.md); no compliance checks have run yet.

**Keyboard and screen reader:** Enter/Space opens the date picker; Tab stays within it; arrow/Home/End/Page keys navigate the calendar; unavailable dates cannot activate; Escape returns to the date button. Distinguish keyboard focus, selected note, and today. Test actual native focus behavior in Obsidian, not only simulated DOM events.

**File preservation:** Snapshot fixture-vault Markdown paths and hashes before and after all navigation-only checks. They must be identical. For tests that deliberately rename/delete fixtures, take a new baseline after the test mutation. No newly created note, template expansion, or content edit is allowed.

**Performance and cleanup:** Exercise a 10,000-note synthetic history and batched filesystem events. Check responsiveness, one index rebuild per coalesced burst, no rebuild on ordinary content edits, and no activity after unload. Record measured timings and environment rather than claiming an unmeasured latency target.

**User acceptance:** Find one specific old note containing remembered information, then browse across one known gap in the user's history. Retrieval should work directly from the header without using the file tree.
