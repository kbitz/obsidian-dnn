## Problem and agreed interaction

Make it easy to find something in an older daily note without navigating the file tree. The user wants this in the existing note header, where their eyes already go for the date.

Replace the daily note's center breadcrumb with:

```text
‹    2026-09-16    ›
```

- Replace the folder path and filename breadcrumb only on recognized daily notes.
- Display the date in `YYYY-MM-DD`, exactly as requested.
- Clicking the date opens the date picker. No chevron, calendar icon, or other toggle beside the date.
- Previous and next move chronologically through existing daily notes, skipping missing dates.
- Strictly browse existing notes. No creation, templates, backfilling, or prompts to create a missing note.
- Use Obsidian's core Daily Notes folder setting as the source of truth. Never hardcode a particular user's folder or maintain a separate folder choice in this plugin.
- Preserve the separate history buttons and other header actions. Normal notes retain their normal breadcrumb.

The user explicitly preferred replacing the breadcrumb over adding controls alongside it: the folder path is redundant here. They also removed the dropdown indicator, chose existing notes only, and clarified that recognition must follow the existing Daily Notes folder setting for every user. These are settled decisions.

## Interaction details

Companion wireframe: [HTML sketch](daily-note-navigation.html) and [rendered sketch](daily-note-navigation.png). These use example dates and neutral styling; they are not an implementation.

Open notes in the pane whose header was used. Navigation participates in ordinary Obsidian history. Disable the previous/next button at the earliest/latest existing date; do not wrap. With one daily note, both arrows are disabled and the date still opens the picker.

The date opens a compact calendar anchored beneath it, initially showing the current note's month. Provide previous/next month controls, a month selector, and a directly editable year so reaching an old year does not require repeated clicks. Bound year selection to the years containing recognized notes. Existing dates are selectable; missing dates are muted and disabled. Distinguish the open note from today. Selecting an existing date opens it and closes the picker. Selecting the current date just closes it. An empty month says “No daily notes this month.” A Today shortcut opens today's note only if it exists; otherwise it is disabled.

Make the date look like the surrounding header text at rest, with a subtle hover treatment and visible keyboard focus. Use real buttons with descriptive accessible names. Enter/Space opens the picker; Escape and outside click close it. Keep keyboard traversal inside the open picker and return focus to the date on dismissal. Calendar keyboard behavior and screen-reader labels must be checked during engineering review. Use the active theme's colors, typography, and spacing.

## Scope and local evidence

User-requested addition during engineering review: use Obsidian's command palette and Settings → Hotkeys for missing actions. Core Daily Notes already supplies previous/next commands, which remain unchanged. Add Open date picker and Open today's existing daily note, mirroring the picker and Today actions while a recognized daily note is active. The picker command requires the visible header anchor. The built-in Today command can create notes, so it cannot implement the existing-only action. Ship no default shortcut assignments or separate shortcut settings. Ordinary picker keyboard/focus behavior is an implementation and acceptance-testing responsibility; the reviewer withdrew the speculative keyboard-isolation approval gate after the user's challenge.

Read-only inspection of the active vault configuration found the daily-note folder `* Daily Notes`; no custom date format is set. The active theme is Dracula Official. Obsidian documents `YYYY-MM-DD` as the default format. [Daily Notes documentation](https://obsidian.md/help/plugins/daily-notes)

The observed folder is an example, not a default or a build-time constant. Resolve the folder and date format from core Daily Notes settings. An empty folder means the vault root; an absent date format means the documented default `YYYY-MM-DD`. Parse each Markdown file's full path relative to that folder using the configured format, including date-derived subfolders, and require a valid date plus a matching formatted path. Do not recognize unrelated date-shaped files elsewhere. Display the recognized date as `YYYY-MM-DD` regardless of its filename format. Obsidian documents custom formats with subfolders in its [Daily Notes documentation](https://obsidian.md/help/plugins/daily-notes).

Re-read those settings before each navigation/picker action and when panes are reconciled; if folder or format changed, rebuild recognition and restore any now-ineligible headers before proceeding. If core Daily Notes is disabled, settings cannot be read, or the format cannot unambiguously identify a day, preserve the normal breadcrumb and explain the prerequisite once. Never guess a folder or silently fall back to scanning the vault.

First release: desktop with core Daily Notes as the settings provider. Periodic Notes-only configurations, mobile, previews, full-text search, and community publication are deferred. Note contents are not needed for recognition.

## Approaches considered

| Approach | Fit and tradeoff |
| --- | --- |
| Add arrows and a picker beside the current breadcrumb | Smallest UI change, but duplicates the date and preserves clutter. Rejected by the user. |
| Replace the daily-note breadcrumb with an integrated navigator | Selected interaction. Keeps navigation where the date already lives; header integration needs runtime verification. |
| Use an existing sidebar calendar | Avoids building a calendar, but changes location and does not replace the breadcrumb. The existing Calendar plugin documents a sidebar view. [Calendar plugin](https://github.com/liamcain/obsidian-calendar-plugin) |

## Engineering direction and remaining check

Use a small TypeScript plugin with a date/file index, a calendar view, and an isolated header adapter. Reuse Obsidian file and lifecycle APIs. Refresh the index on file create/delete/rename, including folder renames, and reconcile each open Markdown pane independently. Revalidate a target before opening it; a deleted target gives a brief notice and refreshes the calendar without creating anything. Treat dates as calendar dates, avoiding UTC conversion shifts.

The published API exposes view containers, header actions, workspace events, and file opening, but the reviewed View/ItemView/MarkdownView declarations do not expose a breadcrumb replacement hook. A contained DOM adapter is therefore a proposed approach, not verified compatibility. First verify header mounting, rerenders, and restoration in the installed app and Dracula theme. [Obsidian API declarations](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)

Only hide the breadcrumb after mounting succeeds. Restore it when leaving a daily note, unloading the plugin, or losing the expected header structure. Avoid global selectors and modifications to Obsidian prototypes. Handle multiple panes, pop-out windows, source/preview modes, and layout changes without duplicated controls or stale listeners. If the header is hidden, leave that preference intact. Version compatibility and the minimum supported app version remain engineering checks.

## Success criteria

- From `2026-09-16`, previous opens the nearest earlier existing note even when several days are missing; next reverses the move.
- A date several years ago can be reached through month/year selection and one day selection.
- Missing dates, missing today, invalid filenames, and deleted targets never create or modify files.
- Changing the Daily Notes folder redirects recognition to that folder; date-shaped files outside it are ignored. An empty folder setting and custom date formats with subfolders work, while the displayed date remains `YYYY-MM-DD`.
- Header text is exactly `YYYY-MM-DD`, with only the two navigation arrows around it.
- Non-daily notes, history buttons, and other panes keep the correct behavior.
- Disabling/re-enabling the plugin restores/replaces the breadcrumb cleanly with no duplicate controls.
- Keyboard navigation and narrow panes remain usable in Dracula and the default theme.
